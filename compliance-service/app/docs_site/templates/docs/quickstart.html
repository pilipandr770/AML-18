Quickstart

From zero to a screened transfer in about 15 minutes. You need a backend that can make HTTPS requests.

1. Get an API key

Register at /developer/signup (name, contact email, optional webhook URL). The key looks like aml18_sk_… and is shown once. Keep it in an environment variable:

export AML18_KEY="aml18_sk_..."
export AML18_URL="https://{{ request.host }}"
The key is a secret. Call the API from your server, never from browser or app code. If it leaks, rotate it with POST /developer/api-key/rotate.

2. Screen a person

curl -s -X POST "$AML18_URL/screening/check-name" \
  -H "Authorization: Bearer $AML18_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Viktor Bout", "date_of_birth": "1967-01-13", "country": "RU"}'

Response (shortened): {"decision": "review", "score": 90.0, "matches": [{"sanctioned_name": "Viktor Anatolijevitch BOUT", "name_score": 90.0, "rule_branch": "…"}]}. Date of birth and country are optional but corroborate a match and cut false positives.

3. Screen a wallet address

curl -s -X POST "$AML18_URL/screening/check-address" \
  -H "Authorization: Bearer $AML18_KEY" -H "Content-Type: application/json" \
  -d '{"address": "0x8576acc5c05d6ce88f4e49bf65bdf0c62f91353c"}'

Response: {"listed": true, "decision": "rejected", "matches": [{"source": "OFAC_SDN", …}]}. An exact listed-address match returns rejected; a human still confirms.

4. Send an incoming transfer to the agent

This is the call most companies wire into their deposit handler.

curl -s -X POST "$AML18_URL/agent/transfers" \
  -H "Authorization: Bearer $AML18_KEY" -H "Content-Type: application/json" \
  -d '{
    "external_ref": "deposit-48213",
    "chain": "sepolia", "asset": "ETH", "amount": "0.5",
    "tx_hash": "0x…", "deposit_address": "0x…your deposit address…",
    "counterparty_name": "Maria Schneider", "counterparty_country": "DE",
    "counterparty_address": "0x…sender…", "memo": "invoice 2026-114"
  }'

You get 201 with the case: case_id, status (auto_cleared or awaiting_human), classification, the deterministic result, a plain-language explanation and whether the on-chain funds were verified. Sending the same tx_hash again returns the existing case with 200, so retries are safe.

The same in Python

import os, requests

def screen_deposit(deposit):
    r = requests.post(
        f"{os.environ['AML18_URL']}/agent/transfers",
        headers={"Authorization": f"Bearer {os.environ['AML18_KEY']}"},
        json={
            "external_ref": deposit.id, "chain": deposit.chain, "asset": deposit.asset,
            "amount": str(deposit.amount), "tx_hash": deposit.tx_hash,
            "deposit_address": deposit.to_address,
            "counterparty_name": deposit.sender_name,
            "counterparty_address": deposit.from_address,
        },
        timeout=30,
    )
    r.raise_for_status()
    case = r.json()
    if case["status"] != "auto_cleared":
        hold_funds(deposit)            # your system: wait for a human decision
    return case

And in Node.js

async function screenDeposit(d) {
  const r = await fetch(`${process.env.AML18_URL}/agent/transfers`, {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.AML18_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({ external_ref: d.id, chain: d.chain, asset: d.asset, amount: String(d.amount),
      tx_hash: d.txHash, deposit_address: d.toAddress, counterparty_name: d.senderName,
      counterparty_address: d.fromAddress }),
  });
  if (!r.ok) throw new Error(`AML+18 ${r.status}`);
  const c = await r.json();
  if (c.status !== "auto_cleared") await holdFunds(d);
  return c;
}

5. Look up a case later

curl -s "$AML18_URL/agent/cases/<case_id>" -H "Authorization: Bearer $AML18_KEY"

What happens when it is down?

Design for failure on your side. If a call times out or returns 5xx, treat the deposit as not cleared and retry; do not release funds on silence. The agent itself fails closed: if the AI model is unavailable the case becomes awaiting_human, never cleared.
