One building block, three regulatory requirements

AML+18 is the compliance foundation your crypto or fintech project can build on — not a finished product for one particular business model. It turns a bare blockchain address into a verified entity: sanctions screening, proof of wallet control, age verification. What you build on top — exchange, wallet, payment service, platform — is up to you; licences and permits for your specific business model are outside this building block.

Travel Rule screening

Sanctions screening for crypto transfers between two VASPs over the real TRISA protocol. Requires your own TRISA node — there is no REST registration here.

Wallet ownership verification

Proof of control over a self-hosted wallet address for transfers above a threshold. REST API, ready to use.

Age verification

Privacy-preserving yes/no age proof, for adult content as well as online gambling. REST API, ready to use.

AI compliance agent

Screens every inbound transfer, explains each decision, and acts only within the policy you set. MONITOR mode by default; POST /agent/transfers.

REST quick start (wallet ownership & age verification)

After registering you receive an API key. Every call carries it as a bearer token:

Wallet ownership verification

# Does this transfer need to be checked at all?
curl "http://localhost:8300/wallet-ownership/requirement?transfer_amount_eur=1500" \
  -H "Authorization: Bearer aml18_sk_..."

# Request a challenge and have the customer sign it with the wallet key
curl -X POST http://localhost:8300/wallet-ownership/challenges \
  -H "Authorization: Bearer aml18_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"network": "ETH", "address": "0x..."}'

# Submit the signature
curl -X POST http://localhost:8300/wallet-ownership/verifications \
  -H "Authorization: Bearer aml18_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"method": "signed_message", "challenge_id": "...", "signature": "0x..."}'

Age verification

curl -X POST http://localhost:8300/age-verify/check \
  -H "Authorization: Bearer aml18_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"subject_reference": "platform-user-123", "proof_token": "mock:over18"}'

Full endpoint reference: see the project's README.md.

Travel Rule entry point (TRISA)

For real sanctions screening of VASP-to-VASP transfers you run your own TRISA node and connect it over the official protocol — no API key from this page is needed or sufficient. Details and a working demo script: examples/travel-rule-demo/README.md in the project repository.
